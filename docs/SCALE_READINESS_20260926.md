# 流量突增准备度审计 — 2026-09-26

## 范围与结论

基于当前仓库代码、迁移和调度脚本的只读审查。没有对生产环境施加负载，没有核实当前云端计算规格、实际 SQL 定义、调度状态、账单或最新监控，也没有修改已提交 Apple 审核的版本。因此本文不提供“能承受多少同时在线用户”的保证。

已有基础：设备级推送队列、领取锁与重试、重复事件保护、发送前权限复查、客户端部分请求合并、临时故障保留会话。主要风险是航班额度、通知积压、完整数据刷新和缺少真实业务容量验证。

## 优先级

### P0：航班查询的全局启动配额

- `supabase/migrations/20260906030000_trip_flight_lookup.sql:29`：未命中缓存的查询，全 App 共用 50 次/日，单账号 10 次/小时；失败查询也消耗额度。
- `supabase/migrations/20260909010000_trip_live_updates.sql:140`：后台共用其中最多 20 次/日。
- `supabase/functions/_shared/trip-worker.mjs:4` 与 `supabase/snippets/schedule_trip_worker.sql`：每次任务只更新一个航班，参考调度为每 5 分钟一次。
- 建议：先核实生产定义和供应商额度；合并同航班同日期的并发查询，按离起飞时间远近安排刷新；额度改为可配置并保留成本上限。额度不足时仍允许手动填写航班。提高供应商费用需单独确定预算。

### P0：推送吞吐量与提醒时效

- `supabase/functions/push-worker/index.ts:214`：同城通知每轮取 20 条，发送并发为 3；参考调度为每分钟一次。
- 若只有这一个定时消费者、没有失败或新增任务，1,000 条设备投递约需 50 轮；这只是队列模型，不是生产实测或 APNs 展示时延保证。
- `supabase/migrations/20260917010000_trip_booking_reminders.sql:105`：自动订票提醒在当地 09:00–10:00 有效；每轮取 20 条，拥堵可能使提醒过期。领取前还会生成和清理任务，涉及对历史记录的检查。
- 建议：把任务生成与发送分开；按时间范围和上限分批生成；按队列积压扩展消费者，保留锁与去重；对最老待发任务、过期任务和重试设告警，规划历史记录清理。

### P1：减少完整快照刷新与数据库往返

- `WhereIsMyFriend/Features/Friends/FriendsView.swift:157`：前台好友页每 60 秒刷新；`Core/AppStore.swift:184` 随后刷新旅行计划。
- 好友计划页与 Trips 页也有 60 秒刷新循环；已有部分防重复请求机制，但仍应测量跨页面和重新进入前台时的总请求量。
- `supabase/migrations/20260906010000_unified_trips_foundation.sql:117`：行程列表聚合每个行程的完整快照，包括成员、航班、备注。好友计划查询也没有分页。
- `supabase/functions/api/index.ts:148`：每次业务请求先调用 Auth getUser，再查询账号映射，最后调用业务 RPC。
- 建议：列表只返回摘要，详情按需加载，历史行程及好友计划分页；共享刷新调度、失败退避与随机错峰，减少无变化刷新。评估非对称签名的验证缓存，但必须保留账号禁用/删除检查，不能仅解码令牌。

### P1：账号级保护与可恢复体验

- 已有航班限额、重复邀请冷却和人工提醒冷却；在 API 入口未发现覆盖全部业务的统一账号/来源限流。
- 建议为注册后初始化、邀请、搜索和内容创建分别设置合理上限；对多次重试的写操作核对幂等性。故障时保留旧数据和输入，避免反复弹出同步提示；只有无法完成用户操作时给出明确恢复入口。

### P0/P1：发布前容量证据与监控

- 164 项单元测试证明逻辑回归通过，不代表千人并发通过。现有 `verify-worker-load.mjs` 主要检查未认证探测响应，不是完整登录用户的业务压力测试。
- 在隔离环境使用合成账号、模拟航班供应商与推送接收端，分别测试注册高峰、已有好友用户同时刷新、密集计划重叠和当地 9 点提醒高峰。
- 逐级测试 100/500/1,000 活跃虚拟用户，并记录具体请求速率与测试数据规模；这些是测试档位，不是已测容量。
- 记录登录成功率、业务接口 95% 请求耗时、错误率、数据库连接/锁等待、最老通知等待时间和航班额度消耗。确定验收指标后再决定是否升级计算资源。
- 上线保障还应核实当前备份与恢复能力、生产/测试隔离和可回滚部署步骤；不能从仓库判断云端已经配置。

## 推荐执行顺序

1. 核实生产配额、调度与资源规格，建立监控基线。
2. 优先修通知吞吐和航班配额分配，同时保留成本保护。
3. 优化刷新、列表摘要与分页。
4. 在隔离环境压测、演练恢复，再决定扩容规模。
